# HBOS Persistence Design
*(Root principle – **Qdrant** is the single source of truth for all HBOS state)*

---

## 1️⃣ `hbos_providers` Schema
Stores **catalogue information** for every LLM provider that HBOS can route to. Each record is persisted as a single Qdrant **payload document** (JSON) and indexed on `provider_id` & `type`.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "hbos_providers",
  "type": "object",
  "required": ["provider_id", "type", "endpoint", "auth", "model_index"],
  "properties": {
    "provider_id": {
      "type": "string",
      "description": "Globally unique ID – e.g. `free_llm_api`, `kiro_gateway`"
    },
    "type": {
      "type": "string",
      "enum": ["FreeLLMAPI", "KiroGateway"],
      "description": "Logical group / deployment"
    },
    "endpoint": {
      "type": "string",
      "format": "uri",
      "description": "Base URL (e.g. `http://FreeLLMAPI:3001`)"
    },
    "auth": {
      "type": "object",
      "properties": {
        "api_key": { "type": "string" },
        "oauth": {
          "type": "object",
          "properties": {
            "client_id": { "type": "string" },
            "client_secret": { "type": "string" }
          },
          "required": ["client_id", "client_secret"]
        }
      },
      "description": "Auth mechanism – only one branch used per provider"
    },
    "model_index": {
      "type": "object",
      "description": "Mapping of model‑type → list of model‑ids hosted by this provider",
      "additionalProperties": {
        "type": "array",
        "items": { "type": "string" }
      },
      "example": {
        "Gemini": ["gemini‑1‑pro‑001", "gemini‑1‑flash‑001"],
        "Claude": ["claude‑v2‑0", "claude‑instant‑1‑0"],
        "GPT": ["gpt‑4‑turbo", "gpt‑3‑5‑turbo"]
      }
    },
    "last_sync": {
      "type": "string",
      "format": "date-time",
      "description": "When the provider’s model catalogue was last reconciled with Qdrant"
    },
    "metadata": {
      "type": "object",
      "additionalProperties": true,
      "description": "Arbitrary free‑form tags (e.g. `region`, `owner`, `quota`) "
    }
  },
  "additionalProperties": false
}
```

**Key points**
* `model_index` is *normalized* – it contains **all** models the provider reports.
* For the current ecosystem:

| Provider | Total Models | Breakdown |
|----------|-------------|-----------|
| `FreeLLMAPI` (port 3001) | **268** | 9 Gemini, 9 Claude (canonical), 250 GPT variants |
| `KiroGateway` | **42** | 12 Gemini, 15 Claude, 15 GPT |

## 2️⃣ `hbos_runtime_state` Schema
Captures the **real‑time operational state** of the HBOS runtime, including active sessions, circuit‑breaker states, and load metrics. This data is ephemeral but must survive restarts.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "hbos_runtime_state",
  "type": "object",
  "required": ["session_id", "state", "last_heartbeat", "circuit_breakers", "load_metrics"],
  "properties": {
    "session_id": {
      "type": "string",
      "description": "Unique identifier for the runtime session"
    },
    "state": {
      "type": "string",
      "enum": ["initializing", "active", "degraded", "shutdown"],
      "description": "Current lifecycle state"
    },
    "last_heartbeat": {
      "type": "string",
      "format": "date-time",
      "description": "Timestamp of last successful health check"
    },
    "circuit_breakers": {
      "type": "object",
      "description": "Per‑provider circuit‑breaker status",
      "additionalProperties": {
        "type": "object",
        "properties": {
          "state": { "type": "string", "enum": ["closed", "open", "half_open"] },
          "failure_count": { "type": "integer" },
          "last_failure": { "type": "string", "format": "date-time" },
          "next_attempt": { "type": "string", "format": "date-time" }
        },
        "required": ["state", "failure_count"]
      }
    },
    "load_metrics": {
      "type": "object",
      "properties": {
        "active_sessions": { "type": "integer" },
        "requests_per_second": { "type": "number" },
        "avg_latency_ms": { "type": "number" },
        "error_rate": { "type": "number" }
      }
    },
    "active_routes": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "route_id": { "type": "string" },
          "provider_id": { "type": "string" },
          "model_id": { "type": "string" },
          "status": { "type": "string", "enum": ["active", "draining", "failed"] }
        }
      }
    }
  },
  "additionalProperties": false
}
```

**Key points**
* Updated on every health‑check cycle (default: 5 s).
* Circuit‑breaker state is **persisted immediately** to prevent thundering herd on restart.
* `active_routes` is a *snapshot* of current routing table; reconciled with `hbos_providers` on startup.

## 3️⃣ `hbos_integrations` Schema
Defines how HBOS connects to **external systems** (databases, message queues, monitoring back‑ends). Each integration is a Qdrant document with connection details and health metadata.

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "hbos_integrations",
  "type": "object",
  "required": ["integration_id", "type", "endpoint", "status", "last_check"],
  "properties": {
    "integration_id": {
      "type": "string",
      "description": "Unique integration identifier (e.g. `postgres_main`, `rabbitmq_events`)"
    },
    "type": {
      "type": "string",
      "enum": ["database", "message_queue", "monitoring", "storage"],
      "description": "Integration category"
    },
    "endpoint": {
      "type": "string",
      "format": "uri",
      "description": "Connection endpoint (URL or DSN)"
    },
    "auth": {
      "type": "object",
      "description": "Integration‑specific credentials",
      "additionalProperties": true
    },
    "status": {
      "type": "string",
      "enum": ["healthy", "degraded", "unreachable"],
      "description": "Last known health status"
    },
    "last_check": {
      "type": "string",
      "format": "date-time",
      "description": "Timestamp of last successful health probe"
    },
    "config": {
      "type": "object",
      "description": "Integration‑specific configuration (pool sizes, timeouts, etc.)",
      "additionalProperties": true
    },
    "metadata": {
      "type": "object",
      "additionalProperties": true,
      "description": "Free‑form tags (e.g. `owner`, `environment`, `version`) "
    }
  },
  "additionalProperties": false
}
```

**Key points**
* All integrations are **probed every 30 s**; failures trigger alerts and circuit‑breaker updates.
* `config` is *immutable* after creation; changes require a new integration record.

## 4️⃣ R‑PERSIST‑RUNTIME
**Runtime Persistence Layer** – defines the mechanism for persisting runtime state to Qdrant.

### 4.1 Collection Layout
| Collection | Purpose | Payload Fields | Vector Field |
|------------|---------|----------------|--------------|
| `hbos_providers` | Provider catalogue | `provider_id`, `type`, `endpoint`, `auth`, `model_index`, `last_sync`, `metadata` | `provider_id` (keyword) |
| `hbos_runtime_state` | Runtime state | `session_id`, `state`, `last_heartbeat`, `circuit_breakers`, `load_metrics`, `active_routes` | `session_id` (keyword) |
| `hbos_integrations` | Integration config | `integration_id`, `type`, `endpoint`, `auth`, `status`, `last_check`, `config`, `metadata` | `integration_id` (keyword) |

### 4.2 Write Path
1. **Session State** – on every health‑check, the runtime updates its `hbos_runtime_state` document using **point update** (`update_point`).
2. **Circuit‑Breaker** – state changes (open/close/half‑open) are written **immediately** with `upsert_point`.
3. **Provider Sync** – when a new model list is fetched from a provider, the `hbos_providers` document is updated via `upsert_point` and `last_sync` is refreshed.

### 4.3 Read Path
* **Startup** – load all `hbos_providers`, `hbos_integrations`, and the **latest** `hbos_runtime_state` (query by `session_id` ordered by `last_heartbeat` descending, limit 1).
* **Routing** – query `hbos_providers` filtered by `type` and `model_index` containing the requested model.
* **Health** – query `hbos_integrations` filtered by `status` != `healthy`.

### 4.4 Consistency Model
* **Strong consistency** for writes (Qdrant default).
* **Eventual consistency** for reads during rebalancing; mitigated by using `prefer_local` flag.

## 5️⃣ Restore
Procedures for restoring HBOS state after a failure or migration.

### 5.1 Full Restore
1. **Stop** all HBOS services.
2. **Drop** existing Qdrant collections (`hbos_providers`, `hbos_runtime_state`, `hbos_integrations`).
3. **Recreate** collections with the same vector configuration.
4. **Restore** from the latest snapshot (taken daily) using Qdrant’s snapshot API.
5. **Start** HBOS services; they will reconcile runtime state with persisted data.

### 5.2 Partial Restore
* **Provider catalogue** – if a provider’s model list is corrupted, restore only that document from the last known good snapshot or re‑sync from the provider.
* **Runtime state** – if the runtime state is lost, HBOS will start with `state: initializing` and rebuild circuit‑breakers from the last heartbeat.

### 5.3 Rollback
* All writes are **idempotent** (document IDs are deterministic). Rolling back to a previous state is achieved by restoring an earlier snapshot.

## 6️⃣ Verification
Ongoing checks to ensure data integrity and consistency.

### 6.1 Schema Validation
* On every write, validate the payload against the JSON‑Schema defined in each section.
* Reject writes that fail validation; log the error and alert.

### 6.2 Cross‑Collection Consistency
* **Provider ↔ Runtime** – verify that every `provider_id` in `hbos_runtime_state.active_routes` exists in `hbos_providers`.
* **Integration ↔ Runtime** – verify that every integration referenced in `hbos_runtime_state` has a corresponding record in `hbos_integrations`.

### 6.3 Health Checks
* **Liveness** – every 5 s, the runtime pings each provider endpoint and updates `last_sync` in `hbos_providers`.
* **Readiness** – every 30 s, the runtime queries Qdrant for the latest `hbos_runtime_state` and verifies `state` is `active`.

### 6.4 Audit Log
* All mutations are appended to an **immutable audit log** (stored as a separate Qdrant collection `hbos_audit`).
* Each entry contains: `timestamp`, `operation` (upsert/delete), `collection`, `document_id`, `previous_version`, `new_version`.

---

## 7️⃣ Migration
Strategies for evolving the persistence schema without downtime.

### 7.1 Backward‑Compatible Changes
* **Additive** – new optional fields can be added to any schema without breaking existing clients.
* **Example** – adding a `region` field to `hbos_providers.metadata` is safe.

### 7.2 Breaking Changes
* **Version bump** – when a breaking change is required, increment the schema version (e.g., `hbos_providers_v2`).
* **Dual‑write** – during the transition period, write to both old and new collections. Read from the new collection; fall back to old if missing.
* **Cutover** – once all data is migrated, switch reads to the new collection and retire the old one.

### 7.3 Data Transformation
* Use a **migration script** that:
  1. Reads from the old collection.
  2. Transforms the document according to the new schema.
  3. Upserts to the new collection.
  4. Verifies the count and sample documents.
* The script is run as a **background job** with progress reporting.

### 7.4 Rollback Plan
* Keep the old collection **until** the new one has been verified for at least 24 h.
* If issues arise, switch reads back to the old collection and abort the migration.
